A fresh Expo project has fewer directories than a bare React Native one, and the missing ones
are the point: there is no `ios/` and no `android/` because those are generated. This page
walks the tree the SDK 57 default template produces and says, for each entry, whether it is
yours, generated, or cache.

## Basic example

What `npx create-expo-app@latest MyApp` leaves on disk, before you run anything:

```text
MyApp/
├── app.json                  # the app config — your app's identity and native settings
├── package.json              # dependencies, pinned to the SDK 57 set
├── tsconfig.json             # extends expo/tsconfig.base
├── .gitignore
├── README.md
├── LICENSE
├── AGENTS.md                 # coding-agent instructions, generated
├── CLAUDE.md                 # ditto
├── .claude/settings.json     # ditto
├── .vscode/                  # recommended extensions and settings
├── assets/
│   ├── expo.icon/            # the iOS icon source referenced by ios.icon
│   └── images/               # icon, splash image, adaptive icon layers, favicon
├── scripts/
│   └── reset-project.js      # moves the demo app aside, leaves you a blank one
└── src/
    ├── app/                  # Expo Router routes — the file tree IS the navigation
    │   ├── _layout.tsx       # root layout, wraps every route
    │   ├── index.tsx         # the "/" route
    │   └── explore.tsx       # the "/explore" route
    ├── components/           # your components, not routes
    │   └── ui/
    ├── constants/
    │   └── theme.ts
    ├── hooks/
    └── global.css
```

`create-expo-app` also runs `git init`, so the project is already a repository with one
commit. The `AGENTS.md` / `CLAUDE.md` / `.claude/` trio is generated by default; pass
`--no-agents-md` at creation time if you do not want them.

After the first `npx expo start`, three more entries appear, all generated and all
git-ignored:

```text
MyApp/
├── .expo/                    # dev server state, caches, generated route types
├── expo-env.d.ts             # one-line type reference, regenerated every start
└── node_modules/
```

## How it works

### There is no `ios/` or `android/` — that is deliberate

The default template's `.gitignore` ends with:

```text title=.gitignore
# generated native folders
/ios
/android
```

The native projects are **build output**. They are produced from `app.json` plus your
installed packages when you run `npx expo prebuild`, `npx expo run:ios` or
`npx expo run:android`, and they are regenerated whenever that runs again. Treating them as
source is the single most expensive mistake available in an Expo project — see
[Continuous Native Generation](../expo-core-concepts/continuous-native-generation.md) for
the mental model and [expo prebuild](../expo-core-concepts/prebuild.md) for the destructive
part.

If a directory appears after a build, do not edit it. Edit the config that produced it.

### `src/app/` is routing, not a components folder

On SDK 57's default template, everything under `src/app/` is a route. A file at
`src/app/settings.tsx` becomes the `/settings` route with no registration step anywhere. A
file at `src/app/_layout.tsx` wraps the routes beside and below it.

This is why `src/components/` exists separately: a component that is not a screen must not
live under `app/`, or the router will treat it as a route. The distinction trips people up
once and then never again.

Older tutorials put routes in a top-level `app/` directory. Both work — Expo Router looks for
`app/` at the project root and inside `src/` — but SDK 57's default template uses `src/app/`,
and mixing the two in one project is ambiguous. Pick one.

[The app Directory](../expo-router/app-directory.md) covers the routing rules properly.

### The entry point depends on the template

There is no `index.js` in the default template. Its `package.json` sets:

```json title=package.json (excerpt)
{
  "main": "expo-router/entry",
  "scripts": {
    "start": "expo start",
    "android": "expo start --android",
    "ios": "expo start --ios",
    "web": "expo start --web",
    "lint": "expo lint",
    "reset-project": "node ./scripts/reset-project.js"
  }
}
```

`expo-router/entry` is the router's own entry module: it discovers `src/app/`, builds the
route tree and registers the root component. You never call `registerRootComponent` yourself.

The `blank` and `blank-typescript` templates have no router, so they do have an entry file:

```ts-fragment title=index.ts
import {registerRootComponent} from 'expo';

import App from './App';

// registerRootComponent calls AppRegistry.registerComponent('main', () => App).
// It also sets up the environment identically whether the app loads in Expo Go
// or in a native build.
registerRootComponent(App);
```

If you add Expo Router to a blank project later, you delete that file and change `main` to
`expo-router/entry`.

### `app.json` is the source of native configuration

```json title=app.json (excerpt)
{
  "expo": {
    "name": "MyApp",
    "slug": "my-app",
    "scheme": "myapp",
    "plugins": ["expo-router", ["expo-splash-screen", {"imageWidth": 76}]],
    "experiments": {"typedRoutes": true, "reactCompiler": true}
  }
}
```

Every native-side fact about your app — bundle identifier, permissions, URL scheme, splash
screen, icons — is expressed here or in a config plugin listed here, and flows into the
generated native projects. [The App Config](../expo-core-concepts/app-config.md) is the
reference.

### `tsconfig.json` extends the SDK's base

```json title=tsconfig.json
{
  "extends": "expo/tsconfig.base",
  "compilerOptions": {
    "strict": true,
    "paths": {
      "@/*": ["./src/*"],
      "@/assets/*": ["./assets/*"]
    }
  },
  "include": ["**/*.ts", "**/*.tsx", ".expo/types/**/*.ts", "expo-env.d.ts"]
}
```

Three things matter here:

- **`expo/tsconfig.base` sets `customConditions: ["react-native"]`.** That is what makes your
  project resolve React Native's **legacy** type surface rather than the Strict API. It is
  why `ViewInstance`, `TextInputInstance` and `HostInstance` do not exist for you — those are
  React Native 0.87 types, and SDK 57 is on 0.86.3. Type a ref by the component:
  `useRef<TextInput | null>(null)`.
- **The `@/*` alias** points at `src/`, which is why the template's imports read
  `import {ThemedText} from '@/components/themed-text'`.
- **The `.expo/types` glob and `expo-env.d.ts` are in `include`** because the dev server
  generates types into them. Removing them from `include` breaks typed routes.

### `.expo/` and `expo-env.d.ts` are generated on every start

`expo-env.d.ts` is a single reference line plus a comment telling you not to edit it:

```ts-fragment
/// <reference types="expo/types" />
```

`.expo/` holds dev server state, the ESLint cache, logs and — when
`experiments.typedRoutes` is on — the generated route types under `.expo/types/`. The CLI
also adds `expo-env.d.ts` to your `.gitignore` for you if it is missing.

Both are regenerated. Deleting them is a safe thing to try when the dev server behaves
strangely.

## Common patterns

### What belongs in git

| Path | In git? | Why |
| --- | --- | --- |
| `src/`, `assets/`, `app.json`, `package.json`, `tsconfig.json` | **Yes** | Source. |
| the lockfile | **Yes** | Reproducible installs. Exactly one lockfile per repo. |
| `.expo/` | No | Dev server state and caches. |
| `expo-env.d.ts` | No | Regenerated on every start. |
| `node_modules/` | No | — |
| `ios/`, `android/` | **It depends** | Ignored under generation; committed if you have deliberately chosen that model. This is a decision, not a default. See [CNG vs Committed Native Directories](../expo-core-concepts/cng-vs-committed-native.md). |
| `dist/`, `web-build/` | No | Export output. |

### Where to put things that are not routes

A layout that works and stays workable:

```text
src/
├── app/            # routes only
├── components/     # shared presentational components
├── features/       # feature-scoped components, hooks and logic
├── hooks/
├── lib/            # API clients, storage wrappers, pure helpers
└── constants/
```

The only rule the toolchain enforces is the first line: `app/` is routes. Everything else is
convention, and the `@/*` alias means moving directories does not mean rewriting relative
import paths.

### Colocating tests and platform variants

Two file-naming conventions are worth knowing because the default template uses both:

- **Platform extensions.** `use-color-scheme.ts` and `use-color-scheme.web.ts` — Metro picks
  the platform-specific file automatically. Also `.ios.tsx`, `.android.tsx`, `.native.ts`.
- **Route groups.** A directory named `(tabs)` groups routes without adding a URL segment.
  Covered in [Groups](../expo-router/groups.md).

### Resetting the template's demo content

```bash
npm run reset-project
```

The script moves `src/` and `scripts/` aside into `example/` and writes a fresh
`src/app/index.tsx` and `src/app/_layout.tsx`. Run it before your first real commit.

## Common mistakes

- **Committing `ios/` or `android/` by accident, then running prebuild.** The regenerated
  directories overwrite what you committed, and the diff is enormous and unreadable. Decide
  which model you are on and make `.gitignore` match it.
- **Putting a component in `src/app/`.** It becomes a route. Symptoms are a phantom URL and,
  with typed routes on, a route type you did not expect.
- **Having both `app/` and `src/app/`.** Expo Router looks in both places. Pick one; the SDK
  57 default template uses `src/app/`.
- **Removing the `.expo/types` glob from `tsconfig.json` `include`.** Typed routes stop
  resolving and every `href` becomes an error.
- **Editing `expo-env.d.ts`.** It is overwritten on the next `npx expo start`.
- **Two lockfiles in one repo.** `npx expo install` and `npx expo prebuild` both detect the
  package manager from the lockfile. Two lockfiles means two different answers.
- **Assuming a CLI project's layout.** There is no `index.js` entry point registering the
  root component; the default template's `main` is `expo-router/entry`.
