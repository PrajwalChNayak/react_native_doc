Icons and the splash screen are native assets: they are baked into the binary at build time, they
are the first thing a store reviewer and a user see, and none of them can change through an EAS
Update.

This page starts from what `create-expo-app` generates for SDK 57, because the configuration shape
changed from what most tutorials show. There is no top-level `splash` key any more; the splash
screen is configured through the `expo-splash-screen` config plugin.

## Why it exists / when to use it — and when NOT to

Read this before your first store build and whenever you rebrand. Every change here needs a **new
native build**.

For controlling **when** the splash hides at runtime (`preventAutoHideAsync`, `hideAsync`) and for
fonts, see [Fonts and Splash Screens](../expo-sdk/fonts-and-splash-screens.md). This page covers the
assets and their configuration.

## Basic example

This is the icon and splash configuration from a real SDK 57 project generated by
`npx create-expo-app@latest` with the default template. Only the unrelated keys have been removed:

```json title=app.json
{
  "expo": {
    "name": "router",
    "slug": "router",
    "version": "1.0.0",
    "icon": "./assets/images/icon.png",
    "ios": {
      "icon": "./assets/expo.icon"
    },
    "android": {
      "adaptiveIcon": {
        "backgroundColor": "#E6F4FE",
        "foregroundImage": "./assets/images/android-icon-foreground.png",
        "backgroundImage": "./assets/images/android-icon-background.png",
        "monochromeImage": "./assets/images/android-icon-monochrome.png"
      },
      "predictiveBackGestureEnabled": false
    },
    "web": {
      "favicon": "./assets/images/favicon.png"
    },
    "plugins": [
      [
        "expo-splash-screen",
        {
          "backgroundColor": "#208AEF",
          "image": "./assets/images/splash-icon.png",
          "imageWidth": 76
        }
      ]
    ]
  }
}
```

The asset files that template ships, with their dimensions measured from the generated files:

| File | Size | Used by |
| --- | --- | --- |
| `assets/images/icon.png` | 1024 × 1024 | `icon` — the fallback for any platform without its own |
| `assets/expo.icon/` | A directory: `icon.json` plus layer images | `ios.icon` |
| `assets/images/android-icon-foreground.png` | 512 × 512 | `android.adaptiveIcon.foregroundImage` |
| `assets/images/android-icon-background.png` | 512 × 512 | `android.adaptiveIcon.backgroundImage` |
| `assets/images/android-icon-monochrome.png` | 432 × 432 | `android.adaptiveIcon.monochromeImage` |
| `assets/images/splash-icon.png` | 228 × 213 | `expo-splash-screen` `image` |
| `assets/images/favicon.png` | 48 × 48 | `web.favicon` |

All PNGs in the template have an alpha channel.

> [!NOTE] Expo Go vs development build
> Expo Go shows **its own** icon and splash screen. Nothing on this page is visible there. Check
> icons and the splash in a [development build](../expo-development-builds/why-you-need-one.md) or,
> better, a release build installed from a real artifact.

## How it works

### `icon`: the universal fallback

The SDK 57 config types describe `icon` as a local path or remote URL, and recommend a 1024 × 1024
PNG. Expo generates the platform sizes from it. `ios.icon` and `android.icon` override it per
platform, and `android.adaptiveIcon.foregroundImage` overrides both on Android.

### `ios.icon`: a file, an appearance set, or an `.icon` directory

In the SDK 57 types, `ios.icon` accepts three shapes:

| Shape | Example | When |
| --- | --- | --- |
| A path to an image | `"./assets/icon-ios.png"` | One icon for every appearance |
| An object `{light, dark, tinted}` | `{"light": "./i-light.png", "dark": "./i-dark.png", "tinted": "./i-tinted.png"}` | Separate images for the iOS light, dark and tinted home screen appearances |
| A path to an `.icon` directory | `"./assets/expo.icon"` | A layered icon; this is what the default template uses |

The template's `assets/expo.icon` is a directory containing `icon.json` (fill, layer groups, shadow
and translucency settings) and an `Assets/` folder with the layer images. That is the format produced
by Apple's Icon Composer. Edit it with that tool rather than by hand.

The types say the image form should be 1024 × 1024 and follow Apple's interface guidelines,
including colour profile and transparency.

### `android.adaptiveIcon`: layers, not a picture

Android launchers draw an adaptive icon from separate layers and then mask it to a shape the
launcher chooses — circle, squircle, rounded square. The SDK 57 types define four keys:

| Key | What it is |
| --- | --- |
| `foregroundImage` | The foreground layer. Overrides `icon` and `android.icon` on Android. |
| `backgroundImage` | A background layer image. Must have the same dimensions as the foreground. Overrides `backgroundColor`. |
| `backgroundColor` | A background colour. Defaults to white `#FFFFFF`. |
| `monochromeImage` | A single-colour layer used on Android 13+ when the user enables themed icons. |

The types note that `backgroundImage` and `backgroundColor` have no effect without
`foregroundImage`. The template sets both a background image and a colour; the image wins where
both apply.

Because the launcher crops the layers, keep the meaningful part of the foreground well inside the
centre. Android's adaptive icon guidelines define the safe zone; artwork near the edges is cut off
on some launchers and not others, which is how an icon looks fine on your phone and clipped on a
reviewer's.

### `android.predictiveBackGestureEnabled`

Not an icon, but in the same generated block, so it is worth knowing why it is there. The SDK 57
types describe it as enabling Android's predictive back gesture on Android 13 (API level 33) and
later, defaulting to `false`. The template sets `false` explicitly. Turn it on only after testing
your back navigation with it, because it changes how back gestures animate and are intercepted.

### The splash screen: `expo-splash-screen` plugin options

The options below were read from the installed `expo-splash-screen` 57.0.9 plugin types:

| Option | Default | Meaning |
| --- | --- | --- |
| `backgroundColor` | `#ffffff` | Background colour of the splash |
| `image` | none | The image drawn in the centre |
| `imageWidth` | `100` | The width to draw the image at |
| `resizeMode` | `contain` | `contain`, `cover` or `native` (Android supports `native`; iOS accepts `cover` or `contain`) |
| `dark` | none | `{image, backgroundColor}` for dark mode |
| `android` | none | Android-specific overrides |
| `ios` | none | iOS-specific overrides |
| `enableFullScreenImage_legacy` | `false` | A transitional helper the types say will be removed. Do not adopt it. |

The modern splash is **a small centred image on a solid colour** — the template's image is 228 × 213
drawn at a width of 76. A full-screen illustration stretched edge to edge is the old approach, and it
is what `enableFullScreenImage_legacy` exists to keep working during migration.

> [!DANGER] The plugin writes native projects
> Icons and splash options take effect at `npx expo prebuild`, which **clears and regenerates**
> `ios/` and `android/` in SDK 57. Hand edits to the generated icon sets, launch storyboards or
> Android drawables are lost. See [expo prebuild](../expo-core-concepts/prebuild.md).

## Platform differences

:::tabs
@tab iOS
- `ios.icon` can be a single image, `{light, dark, tinted}`, or an `.icon` directory.
- App Store Connect uses the 1024 × 1024 icon from the build for the store listing. It must not
  have transparency problems that show as black areas; follow Apple's icon guidelines.
- The splash is generated into a launch storyboard. `ios.tabletImage` and
  `ios.tabletBackgroundColor` are available for iPad — see
  [Fonts and Splash Screens](../expo-sdk/fonts-and-splash-screens.md).
- Producing and installing an iOS build needs macOS with Xcode, or a hosted service such as EAS
  Build (Expo account required; paid with a free tier).
@tab Android
- The launcher icon comes from `adaptiveIcon` layers; `monochromeImage` serves themed icons on
  Android 13+.
- The Google Play store listing icon is uploaded separately in the Play Console. It is not taken from
  your adaptive icon.
- The splash uses Android's splash screen system. Android-only options include per-density images
  and `resizeMode: "native"`.
- Android builds run on Windows, macOS or Linux with the Android SDK.
:::

## Common patterns

### Variant icons for non-production builds

Give development and preview builds a visibly different icon so nobody files a bug against the wrong
app. With a dynamic config:

```ts-fragment title=app.config.ts
import type {ConfigContext, ExpoConfig} from 'expo/config';

const variant = process.env.APP_VARIANT ?? 'production';

export default ({config}: ConfigContext): ExpoConfig => ({
  ...config,
  name: variant === 'production' ? 'Example' : `Example (${variant})`,
  slug: 'example',
  icon: variant === 'production' ? './assets/images/icon.png' : './assets/images/icon-dev.png',
});
```

This block is marked as a fragment because it reads `process.env`, whose types come from the
project's generated `expo-env.d.ts`. See [Build Profiles per Environment](environments.md).

### Check the real result, not the config

After a build, install it and look at:

- The home screen icon with the device in light mode, dark mode and (iOS) tinted mode.
- The Android icon on two launchers with different mask shapes, and with themed icons on.
- A cold start in light and dark mode for the splash.

An emulator is fine for shapes and colours. Check at least one physical device before release.

## Common mistakes

- **Adding a top-level `splash` key from an old tutorial.** The SDK 57 config types have no
  top-level native `splash` key. Configure the `expo-splash-screen` plugin.
- **Using a full-screen splash illustration.** The splash is a centred image on a colour. Supply a
  small image and set `imageWidth`.
- **Expecting to see the icon or splash in Expo Go.** Expo Go shows its own. Use a build.
- **Artwork touching the edges of `foregroundImage`.** Launchers crop adaptive icons differently.
  Keep the mark inside the safe zone.
- **`backgroundImage` at a different size from `foregroundImage`.** The types require the same
  dimensions.
- **Shipping an icon change as an EAS Update.** Icons are in the binary. Build again.
- **Hand-editing `ios/.../AppIcon.appiconset` or Android `mipmap` folders while using prebuild.**
  Prebuild regenerates them. Change the source assets and the app config.
- **Adopting `enableFullScreenImage_legacy` in a new project.** The types mark it as a transition
  helper that will be removed.
