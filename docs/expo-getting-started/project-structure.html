Project Structure

What every file and directory in a fresh Expo SDK 57 project is for, which ones are generated, and which ones belong in git.

Expo SDK 57 · RN 0.86

A fresh Expo project has fewer directories than a bare React Native one, and the missing ones are the point: there is no ios/ and no android/ because those are generated. This page walks the tree the SDK 57 default template produces and says, for each entry, whether it is yours, generated, or cache.

How it works#

There is no ios/ or android/ — that is deliberate#

The default template's .gitignore ends with:

The native projects are build output. They are produced from app.json plus your installed packages when you run npx expo prebuild, npx expo run:ios or npx expo run:android, and they are regenerated whenever that runs again. Treating them as source is the single most expensive mistake available in an Expo project — see Continuous Native Generation for the mental model and expo prebuild for the destructive part.

If a directory appears after a build, do not edit it. Edit the config that produced it.

src/app/ is routing, not a components folder#

On SDK 57's default template, everything under src/app/ is a route. A file at src/app/settings.tsx becomes the /settings route with no registration step anywhere. A file at src/app/_layout.tsx wraps the routes beside and below it.

This is why src/components/ exists separately: a component that is not a screen must not live under app/, or the router will treat it as a route. The distinction trips people up once and then never again.

Older tutorials put routes in a top-level app/ directory. Both work — Expo Router looks for app/ at the project root and inside src/ — but SDK 57's default template uses src/app/, and mixing the two in one project is ambiguous. Pick one.

The app Directory covers the routing rules properly.

If you add Expo Router to a blank project later, you delete that file and change main to expo-router/entry.

app.json is the source of native configuration#

Every native-side fact about your app — bundle identifier, permissions, URL scheme, splash screen, icons — is expressed here or in a config plugin listed here, and flows into the generated native projects. The App Config is the reference.

tsconfig.json extends the SDK's base#

Three things matter here:

  • expo/tsconfig.base sets customConditions: ["react-native"]. That is what makes your project resolve React Native's legacy type surface rather than the Strict API. It is why ViewInstance, TextInputInstance and HostInstance do not exist for you — those are React Native 0.87 types, and SDK 57 is on 0.86.3. Type a ref by the component: useRef<TextInput | null>(null).

  • The @/* alias points at src/, which is why the template's imports read import {ThemedText} from '@/components/themed-text'.

  • The .expo/types glob and expo-env.d.ts are in include because the dev server generates types into them. Removing them from include breaks typed routes.

.expo/ and expo-env.d.ts are generated on every start#

expo-env.d.ts is a single reference line plus a comment telling you not to edit it:

.expo/ holds dev server state, the ESLint cache, logs and — when experiments.typedRoutes is on — the generated route types under .expo/types/. The CLI also adds expo-env.d.ts to your .gitignore for you if it is missing.

Both are regenerated. Deleting them is a safe thing to try when the dev server behaves strangely.

Colocating tests and platform variants#

Two file-naming conventions are worth knowing because the default template uses both:

  • Platform extensions. use-color-scheme.ts and use-color-scheme.web.ts — Metro picks the platform-specific file automatically. Also .ios.tsx, .android.tsx, .native.ts.

  • Route groups. A directory named (tabs) groups routes without adding a URL segment. Covered in Groups.

Resetting the template's demo content#

The script moves src/ and scripts/ aside into example/ and writes a fresh src/app/index.tsx and src/app/_layout.tsx. Run it before your first real commit.

Common mistakes#

  • Committing ios/ or android/ by accident, then running prebuild. The regenerated directories overwrite what you committed, and the diff is enormous and unreadable. Decide which model you are on and make .gitignore match it.

  • Putting a component in src/app/. It becomes a route. Symptoms are a phantom URL and, with typed routes on, a route type you did not expect.

  • Having both app/ and src/app/. Expo Router looks in both places. Pick one; the SDK 57 default template uses src/app/.

  • Removing the .expo/types glob from tsconfig.json include. Typed routes stop resolving and every href becomes an error.

  • Editing expo-env.d.ts. It is overwritten on the next npx expo start.

  • Two lockfiles in one repo. npx expo install and npx expo prebuild both detect the package manager from the lockfile. Two lockfiles means two different answers.

  • Assuming a CLI project's layout. There is no index.js entry point registering the root component; the default template's main is expo-router/entry.
