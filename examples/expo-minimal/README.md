# Example: expo-minimal

The smallest useful **Expo SDK 57** app. Every other `expo-*` example assumes you have read
this one.

> **Toolchain:** Expo SDK 57 · React Native **0.86.3** · runs in **Expo Go**
>
> This is the Expo half of the handbook. The `examples/minimal-app` project is the React Native
> **Community CLI** equivalent on React Native 0.87.1. They are different React Native versions
> — see [SDK to React Native Pairing](../../content/expo-migration/sdk-react-native-pairing.md).

This project was generated by actually running `create-expo-app`, not written from memory:

```bash
npx create-expo-app@latest expo-minimal --template blank-typescript
```

## What it demonstrates

- **There is no `ios/` or `android/` directory.** Under Continuous Native Generation those are
  *build output*, produced by `npx expo prebuild` or by the build itself. They are not source,
  and this project never needs them to run in Expo Go.
- **Refs typed for React Native 0.86.** `useRef<TextInput | null>(null)` — the per-component
  instance types (`ViewInstance`, `TextInputInstance`, `HostInstance`) that React Native 0.87
  introduced **do not exist in 0.86**. Copying the 0.87 form from the CLI half of this handbook
  is a compile error here, which is exactly the mistake the type-check harness exists to catch.
- **`expo-status-bar`** rather than React Native's `StatusBar` — it handles light/dark contrast
  and behaves the same on both platforms.
- **`tsconfig.json` extends `expo/tsconfig.base`**, which sets `customConditions:
  ["react-native"]` — the *legacy* React Native type surface. SDK 57 does not opt into the
  Strict TypeScript API.

## Run it

```bash
npm install
```

```bash
npx expo start
```

Then press **a** for Android, **w** for web, or scan the QR code with **Expo Go** on a device.
Pressing **i** opens the iOS simulator and requires **macOS with Xcode**.

This example runs in **Expo Go**: it uses no native module outside the ones Expo Go already
bundles. The moment you add a library with custom native code, Expo Go stops being enough —
see [Expo Go vs Development Builds](../../content/expo-core-concepts/expo-go-vs-development-builds.md).

## Installing packages

Always:

```bash
npx expo install expo-image
```

Never `npm install expo-image`. `npx expo install` resolves the version matching your installed
SDK from `expo/bundledNativeModules.json`; a bare `npm install` fetches `latest`, which is
routinely built for a different SDK. Native module mismatches fail at **runtime**, not at
install time.

## Verify

All four of these were run on this project and pass. Node 22.13.0 or newer.

```bash
npm run tsc
```

```bash
npm run check-deps
```

`expo install --check` reports `Dependencies are up to date`.

```bash
npm run config:public
```

`expo config --type public` resolves the app config and reports `sdkVersion: '57.0.0'`.

```bash
npm run export
```

`expo export` bundles **580 modules** into a **1.4 MB** Hermes bytecode file at
`dist/_expo/static/js/android/index-*.hbc`.

That `.hbc` is worth knowing about: it is Hermes **bytecode**, not readable JavaScript — but
string constants survive it intact. That is the basis of the `EXPO_PUBLIC_` demonstration in
[expo-public-leak](../expo-public-leak/README.md).

## The versions this pins, and why

`package.json` pins exactly what `create-expo-app` generated for SDK 57:

| Package | Version |
| --- | --- |
| `expo` | `~57.0.22` |
| `react-native` | `0.86.3` |
| `react` | `19.2.3` |
| `expo-status-bar` | `~57.0.1` |
| `@types/react` | `~19.2.2` |
| `typescript` | `~6.0.3` |

Note **TypeScript 6**. The SDK 57 template pins it, so the handbook's type-check harness uses
6.0.3 too — a block that compiles in the docs compiles in a real project.
